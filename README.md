# RIS 醫師休假代班工具

把「某醫師請假 → 手動改 20~30 列排班」變成「查詢一次 → 按一次 → 檢查 → 存檔」。

---

## 平常怎麼用（GUI，建議用這個）

```
python ris_gui.py
```

1. 在 RIS 的「醫師班表維護」照平常方式查詢（日期 + 排班醫師），**確認畫面上有資料**
2. 按 **「讀取畫面表格」**
3. 模式維持 **「自動對照」** —— 程式會用 `mapping.csv` 幫**每一列各自**決定該換成哪個 OFF 帳號
4. 看清單最右邊的 **「將改成」** 欄。灰字的那幾列是對照表接不到的，程式不會碰，要自己改
5. 不用選列 = 改篩選出來的全部；要只改幾列就用 Ctrl / Shift 點選
6. 第一次用某個帳號時，勾 **「先只改一列試試」**
7. 按 **「開始修改」**，看訊息區
8. **回 RIS 檢查 → 自己按存檔 → 重新查詢**

第 8 步的重新查詢是唯一的真相：查不到資料就代表成功。
訊息區的 `V` 只代表畫面上對了，不代表寫進資料庫了。

一次可以混合多種帳號。例如一天 7 個班分屬 4 種 OFF 帳號，按一次就跑完，約 24 秒。

### 訊息區會看到什麼

| 訊息 | 意思 |
|---|---|
| `核對通過：N 列已改，其他列都沒被動到` | 正常，可以去存檔 |
| `打進 XXX 之後下拉補成 '...'，已按 ESC 取消` | 帳號可能拼錯，該列沒被動到，整批停住 |
| `!! 第 N 列根本不該被動到` | **不要存檔**，重新查詢選「否」還原 |
| `第 N 列內容變了` | 你讀取後又重新查詢過，重按「讀取畫面表格」 |

## 命令列版（`6_plan.py` / `7_apply.py`）

GUI 出現前的舊流程，留著當備援。差別是它多一層 `plan.csv`：
先產生計畫、看過、再套用，適合想留下書面計畫的時候。

`7_apply.py` 的寫入直接用 `ris_gui.py` 裡的 `Ris`，兩邊是同一套邏輯，
所以 GUI 有的安全機制（打字寫入、補完比對、ESC 取消、全表核對）它都有。
`6_plan.py` 全程唯讀，不碰畫面。

### 1. 在 RIS 查詢
開啟「醫師班表維護」，照平常方式填：

- 日期區間 = 請假那天
- 排班醫師 = 請假的醫師
- 按查詢，**確認畫面上有資料**

### 2. 看程式打算改什麼（不會動任何東西）

```
cd D:\Users\G04199\ris-schedule-tool
python 6_plan.py G04564
```

只請半天就加參數：

```
python 6_plan.py G04564 --shift AM     # 只改上半天
python 6_plan.py G04564 --shift PM     # 只改下半天
```

報告會分成幾區：**會修改的** / **需要手動處理的** / **跳過的**。
看過覺得沒問題再進行下一步。計畫會存成 `plan.csv`。

### 3. 實際修改（仍然不會存檔）

```
python 7_apply.py --limit 1      # 第一次或不放心時，先只改一列
python 7_apply.py                # 改全部
```

改完會重讀整張表逐列核對，通過才會告訴你可以去存檔。

### 4. 你自己檢查、你自己存檔

- 看畫面確認改對了
- **按存檔**（程式永遠不會替你按）
- 存完重新查詢一次，查不到資料就代表成功

## 安全設計

| 機制 | 說明 |
|---|---|
| 只改一欄 | 只碰「排班醫師」，其他 10 欄完全不動 |
| 改前核對 | 逐列比對日期、時段、分類、類別、目前醫師，**任何一格對不上就中止** |
| 改後驗證 | 讀回來確認真的變成目標帳號，不符就停 |
| 不存檔 | 寫入資料庫這個不可逆的動作，永遠由人執行 |
| `--limit` | 可以只改前 N 列，用來小規模試跑 |

## 地雷（血淚換來的）

**寫入一定要用鍵盤打字，不可以用 `SetValue`。**
用 `ValuePattern.SetValue` 設值，畫面會變、讀回來也是對的、怎麼驗都過 ——
但 RIS 不認為那一列被編輯過，**存檔時整列跳過**，重新查詢就跳回舊值。
2026-07-23 實測：一次改 9 列，畫面九列全對，存檔後只有 1 列真的進資料庫。
正確做法是模擬真人：點進格子 → Ctrl+A → 打帳號 → 等下拉補完 → 比對 → Enter。

**不可以用上下鍵來「提交」那一列。**
格子的編輯器是個下拉式方塊，方向鍵改的是**選單選到第幾項**，不是游標在第幾列。
選單依字母排序，所以一個 DOWN 就會：
`NEUMRIOFF均分 → PLFOFF均分`、`G04564薛硯中 → G04586陳信銘`。
同一天實測把 8 個班掛到一位完全無關的醫師身上（沒存檔，被全表核對擋下來）。
提交交給 Enter，它同時完成「確認這一格」和「離開這一列」。

**核對一定要重讀全表，不能只看改過的那幾列。**
只檢查目標列的話，「不該動的列被動到」這種錯永遠看不出來。

**不要點表格最左邊的列首。**
點列首會選取整列，此時按存檔 = **刪除該列**，不是儲存修改。
程式已經避開，但你手動操作時也要小心。

**寫入要填帳號，不是顯示的那串字。**
`CCTAOFF均分` 是「帳號 CCTAOFF + 姓名 均分」串起來的。
填 `CCTAOFF` 才對；填 `CCTAOFF均分` 會讓格子無聲變成 `(null)`。

**改完未存檔時不要關視窗或重新查詢。**
會跳出「資料未存檔,是否要存?」，按錯就寫進去了。
要放棄修改就選「否」。

## 這個工具不處理的

| 情況 | 為什麼 | 怎麼辦 |
|---|---|---|
| X 光等均分池的班 | 那些列掛的是 `W1PLAINW1X光均分` 這種池帳號，用醫師名字查不到 | 手動改 |
| 門診/住院分開處理 | 需要把一列「不限」拆成兩列，程式要能新增列，風險高 | 手動改 |
| breast MR | 人力少，由兩人對切，沒有對應的 OFF 帳號 | 手動改 |
| 竹東的班 | 在別的地方設定 | 不處理 |

遇到這些，`6_plan.py` 會列在「需要手動處理」區，不會亂猜。

## 對照表 mapping.csv

決定「哪個班別 → 換成哪個 OFF 帳號」。用 Excel 或記事本編輯。

- `代班帳號` = 實際填進格子的值（例如 `CCTAOFF`）
- `顯示名稱` = 填完畫面會顯示的樣子（例如 `CCTAOFF均分`），程式拿它驗證
- 留空 = 程式不動它，列進「需要手動處理」
- `*` = 這一欄不參與比對
- 由上往下比對，第一個對上的就採用，所以**特例要放在通則前面**

有些規則標著「推測，尚未實際出現過」——那是我從 OFF 帳號命名推的，
第一次遇到那種班別時記得多看一眼。

## 出問題時

**表格讀到 0 列** → 確認畫面有開著、有按過查詢、看得到資料

**「內容跟計畫表對不上，中止」** → 你在產生計畫後又重新查詢過，重跑 `6_plan.py`

**寫入失敗或值變成 (null)** → 重新查詢一次，提示選「否」還原，然後把訊息記下來

**存檔按鈕不亮** → 手動在「排班醫師」欄點一下，再按一下上、一下下
